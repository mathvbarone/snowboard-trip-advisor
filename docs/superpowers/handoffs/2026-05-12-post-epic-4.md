## Phase-1 limitations carried forward

These are forward-looking watch-items for Epic 5+. Each was a deliberate Phase-1 acceptance, not a regression.

### useWorkspaceState in-flight-clear race — residual disk-side divergence

PR 4.6c shipped the AbortController-based fix (path-gated by which paths are in the in-flight draft). The SPA's in-session UX is now consistent: clearing a field mid-PUT reverts in-flight-draft statuses to `dirty` (not `save-failed`), suppresses the response's prepopulate, and skips `lastSentDraft` update.

**Residual:** when the server has atomic-written *before* the abort propagates (likely on localhost with sub-ms latency), the workspace file on disk persists the typed value while the SPA's editor input + canonical correctly show the cleared state. Recovery: re-edit or toggle AUTO. The race fix narrative lives inline in [`apps/admin/src/state/useWorkspaceState.ts`](../../../apps/admin/src/state/useWorkspaceState.ts) (≥12 inline comments naming the decision) and in spec §7.13's `Status: DONE` paragraph.

**Phase 2 watch-item.** The Hono service swap may revisit by either (a) widening the PUT API with a `null`-as-clear semantic for required fields, or (b) enforcing post-write read-back. If Epic 5 / Phase 2 work touches this surface, consider authoring an ADR for the chosen direction.

### Dashboard health-card staleness

`useHealth` re-fetches on each mount but does not subscribe via `useSyncExternalStore` (Tier 4 dropped that wiring for file-budget reasons). The Dashboard's persistent health-card display lags one navigation cycle behind a publish. Acceptable Phase-1 limitation. Revisit when Epic 5 introduces a second mutation surface (Test / Sync) that should also refresh health aggregates.

### `useResortList.__resetForTests` not wired into `apps/admin/src/test-setup.ts`

Pre-existing technical debt from Tier 2. Vitest's per-test-file module isolation makes cross-file leakage impossible; local `afterEach` is sufficient. Out-of-scope for Epic 4. Address opportunistically when Epic 5 touches the test-setup surface.

### `/` keyboard shortcut deferred to Phase 2

Spec §3.10 named 5 global shortcuts; Tier 5 shipped 4. A focus-only placeholder `<input type="search">` violates WCAG 3.3.2 + 4.1.2 (the input claims a search role, does nothing). Ship `/` when search functionality lands (likely Epic 6 polish or a Phase 2 product surface).

### No `apps/admin` production build

Admin is loopback-only per AGENTS.md "Admin App Rules". Dockerfile prod-build guard deferred to Epic 6 per spec §10.7 / C4. CODEOWNERS still flags `Dockerfile` + `.github/workflows/**` as load-bearing surfaces for any PR introducing `COPY apps/admin`.

### Visual-Diff Workflow

`visual:approve` label + screenshots precedent lands with Epic 6 PR 6.3 per AGENTS.md "Visual-Diff Workflow". Epic 5 does not introduce visual-regression machinery.

### Required-CODEOWNER-review on `main`

OFF in Phase 1 (single-maintainer). Original `main` protection JSON preserved at `/tmp/main-protection-pre-relax.json` for reference. Re-enable when a second maintainer joins.

## How to start verification

```bash
git checkout main
git pull
npm install
npm run setup       # regenerates tokens.css; installs hooks
npm run qa          # full chain — must exit 0
npm run dev:admin   # boots 127.0.0.1:5174 strictPort:true
```

Browser smoke at <http://127.0.0.1:5174>:

- **Dashboard** renders with all 8 health cards (cold-start empty state visible when `data/admin-workspace/` + `data/published/current.v1.json` are both absent).
- **`?route=resorts`** shows the sortable + filterable ResortsTable; the Dashboard's "Failed fields" card links here with `hasFailures=true`.
- **Row click** opens the editor; `<ModeToggle>` flips AUTO ↔ MANUAL; typing a numeric value into a durable field debounces 500 ms then PUTs; `data/admin-workspace/<slug>.json` updates with the new value + manual `FieldSource` provenance; reload preserves workspace state.
- **`g r`** navigates to resorts; **`g i`** surfaces a Toast ("Integrations management isn't available yet."); **`mod+enter`** inside the editor flushes the in-flight workspace draft immediately (no 500 ms wait).
- **Below `md` viewport** (≤899 px), the Shell's Publish + Account dropdown buttons render with native `disabled` (removed from tab order, not just CSS-hidden); FieldRow edit inputs are not rendered.
- **Publish button** (top-right) opens PublishDialog; if any of the 4 health blockers fires (`resorts_with_failed_fields > 0`, `resorts_with_missing_provenance > 0`, `resorts_with_corrupt_workspace > 0`, `resorts_total === 0`) the confirm button is disabled with the spec §4.3.1 tooltip text. Confirming a clean publish writes `data/published/history/<counter>-<iso>.json` + updates `data/published/current.v1.json`; **`?route=publishes`** shows the new entry.
