Rejected promises stay pinned in `cachedPromises` per [ADR-0010](../../adr/0010-usedataset-rejected-promise-pinning.md). `prepopulateResortDetail(slug, response)` writes BOTH maps so the next render skips Suspense entirely (no fallback flicker). HMR reset in sibling `useResortDetail.hmr.ts` (coverage-excluded by `apps/admin/vite.config.ts` glob update).

This was a latent 4.4a-2 oversight uncovered by 4.4d's first real `prepopulateResortDetail` consumer. **Tier 4 publish-success can rely on this**: after the publish handler atomic-writes `current.v1.json`, the SPA invalidates affected slugs (or globally) and mounted editors re-render against the updated cache.
- **`apps/admin/src/state/useWorkspaceState.ts`** — module-scoped per-slug `Map<ResortSlug, SlugStore>` singleton (Decision E1+). Every `useWorkspaceState()` consumer in the same editor subscribes via `useSyncExternalStore` to the SAME store for the active slug. 500ms debounce; every `setFieldValue` / `setMode` increments `store.rev`. On PUT-fire, snapshots `store.rev` as `inFlightRev` and sets `store.inFlightToken = Symbol()`. On response, marks `saved` and adopts canonical state only if `store.inFlightToken === token AND store.rev === inFlightRev`. Never fires a second PUT while one is in-flight — queues the next debounced flush via `store.queued`. On success, draft is reset (Decision D13) and `prepopulateResortDetail(slug, response)` replaces canonical cache (avoiding Suspense flicker). `setFieldValue` writes manual `FieldSource` provenance into `draft.resort.field_sources[path]` alongside the value (Decision D12 — preserves the project's "every metric carries a `field_sources` entry" Core Principle).
- **`apps/admin/src/state/useModeToggle.ts`** — per-field AUTO/MANUAL state. Reads `editor_modes`; computes `validPaths = Object.keys(resort.field_sources)`; **silently no-ops** when path ∉ `validPaths` (Codex P2 fold on `e8a2374` — `eslint.config.js:90` blocks `console` in app code, so the schema refinement on the server is the load-bearing safety). `useWorkspaceState` and `useModeToggle` both derive `slug` internally via `useURLState` (Decision D7 — avoids prop-drilling through `MetricPanel.tsx`).

## Known Phase-1 limitations (carried forward, NOT folded in Tier 3)

These are tagged for PR 4.6a (Tier 5 polish) per spec [§7.16](../specs/2026-05-01-epic-4-admin-app-design.md#716-pr-46a--polish-keyboard-shortcuts--responsive-read-only-below-md). **Do not re-litigate them in Tier 4 work — the maintainer accepted the Phase-1 framing by merging PR #95 with these open.**

- **In-flight-clear race in `useWorkspaceState`** (Codex P2-B family, surfaced across 3 of the 4 Codex review rounds on PR #95). When the user types a valid value, the 500ms debounce starts a PUT, and the user clears the input before the PUT resolves: `clearFieldValue` removes the side from the draft; the queued flush hits the empty-diff branch and short-circuits without sending a correction; the workspace file persists the in-flight PUT's value while the editor's `<Input>` shows blank. The DISPLAY (formatted text in the row) reflects the persisted value correctly (via the post-PUT canonical prepopulate + the round-2 P2-C subscription); only the `<Input>` is blank. The status indicator becomes `undefined` (not `saved`), so the misleading-"saved" framing in some Codex comments doesn't fire in this codepath. **Recovery:** re-type to overwrite OR toggle the row to AUTO (`editor_modes[path] = 'auto'`). **Architectural-fix tradeoffs** — Tier 4 must NOT touch this; the fix requires either widening the PUT API with a `null`-as-clear semantic for required fields (contradicts schema's nominal contract) or a client-side `AbortController` race against the in-flight PUT to suppress the response's prepopulate. PR 4.6a polish ships the chosen fix; until then, the limitation stands as a documented Phase-1 acknowledgement.
